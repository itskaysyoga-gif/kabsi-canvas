Task RB-C1 (R-139, `docs/kabsi-3/build-plan.md`), on Rashid's GO. Dark: nothing calls these functions, no row was added to `app_settings` or `location_packs`, no public or WhatsApp behaviour changed, so no facts change.

## What exists

One additive migration, `supabase/migrations/<version>_request_book_reads.sql`, in PR B's style: SECURITY DEFINER, empty `search_path`, qualified names, revoked from public, anon and authenticated, execute for service_role only, and every `private.rb_*` helper executable by no API role. Every function starts with `private.rb_gate`.

| Function | Kind | What it does |
|---|---|---|
| `request_intake_propose(location, actor, key, source, raw_text, field_evidence, provider_message_id)` | Write, idempotent | A pending proposal, `created_by` the checked actor. One per provider message |
| `request_intake_revise(location, actor, key, intake, raw_text, field_evidence)` | Write, idempotent | Only while pending and not expired. A null argument keeps that part |
| `request_intake_discard(location, actor, key, intake)` | Write, idempotent | Only while pending |
| `request_intake_get(location, actor, intake)` | Read | The proposal, read as `expired` once past its time, with its saved request if any |
| `request_get(location, actor, ref)` | Read | By id, `42` or `#42`: the whole request and its customer name |
| `request_find(location, actor, query)` | Read | Keys `number`, `name`, `phone`, `text`; every key given must match; open first, then most recent; 15 rows and `more` |
| `request_list_open(location, actor, filter)` | Read | Keys `kind`, `status`, `unconfirmed`, `due` (a time); most recent first; 15 rows and `more` |
| `customer_suggest(location, actor, name, phone)` | Read | Candidates with `phone_hint` (`***` and the last 4 digits), request count and last seen; `suggestion_only` true; erased customers never returned |

Reads are STABLE, so the database itself refuses any write inside them, `tool_executions` and the audit log included. Name search: trigger `customers_name_key` (BEFORE INSERT OR UPDATE OF display_name) fills `name_key` from `private.rb_fold`, immutable: lower case, trimmed, spaces folded, Arabic-Indic and Eastern Arabic-Indic digits, Arabic short vowels, tatweel, hamza forms of alef, taa marbuta, alef maqsura, and common Latin accents. Phones compare by digits with leading zeros dropped, at least 7 digits, so a local and an international form match.

## Decisions to confirm

- Only the person who proposed a proposal, or an owner or manager, may revise or discard it (same pattern as PR B's Undo).
- `unconfirmed` means an appointment that is missing either confirmation; each row carries `staff_confirmed` and `customer_confirmed` so the words can say which.
- Proposal audit rows use object type `request_intake` and hold only the source or the names of the fields changed.
