# Check 2: finding the right business in the free check (1 Nov 2026)

Lane R's decisions of 1 Nov 2026 on Rashid's finding: searching picked the business at once, there were no suggestions while typing, and the business could not be changed after it was chosen. Branch `claude/check2`. Model: Sonnet 5.5.

## What changed

1. **Suggestions while typing** in every free check box (Home, the industry pages, /scan; the one `ScanBox`): `src/components/kabsi/business-combobox.tsx`. After 3 characters and a 300 ms pause, at most 5 suggestions with the name and a short address. WAI-ARIA 1.2 combobox with a listbox: arrow keys (wrapping), Enter chooses the highlighted option or otherwise submits the search, Escape closes, Tab closes, a polite live region says "5 suggestions. Use the up and down arrow keys, then Enter to choose." or "No suggestions. Press Enter to search." Options are 56 px tall; with the phone keyboard open the page scrolls up (the box stays under the header) and, if the list still does not fit, the list is shortened so the last row and the attribution show.
2. **Through Kabsi's own function, never the browser**: action `suggest` of the existing `profile-snapshot` Edge Function (`supabase/functions/_shared/profile-snapshot.ts`, `suggestHandler`), calling the existing Google layer's `autocomplete` (so `places_take('autocomplete')` counts it and the daily cap applies). Same Turnstile as the free check, once per typing session: the first call carries the Turnstile token and the answer carries a signed pass (HMAC-SHA-256 of visitor and expiry with the Turnstile secret, 15 minutes, tied to the visitor hash), because a Turnstile token works once and typing makes several calls. Own limits per visitor: 20 a minute and 120 an hour (the free check's 10 a minute is not used up by typing; `snapshot:min` and its place before Turnstile are unchanged, a test pins it). Any refusal, the cap or a Google error returns `available: false` and the box becomes a plain search, silently.
3. **Session token ends at Place Details**: the page makes one UUID per typing session; every suggest call carries it; choosing a suggestion goes to `/scan?place=...&st=<token>` and the `check` action passes it to Place Details (`getSnapshotPlace(key, placeId, sessionToken)`). A new token starts the next typing session. A token the server does not recognise as a token is ignored.
4. **Never pick for the visitor**: `scan-live.tsx` no longer picks the only match. One match shows "Is this your business?" with name, address, category and "This is my business"; several show "Pick your business"; both have "Not here? Search again". The search's field mask gained `places.primaryTypeDisplayName` (the same Text Search Pro tier as the name and address) so the category can be shown.
5. **Change it**: every result (/scan and /scan/CODE) has "Not your business? Change it". Both go to `/scan?q=<typed text>&change=true`, which shows the box again with the text kept and looks nothing up.
6. **Attribution**: Google's Places policy ("When displaying Places API data without a Google Map, you must include the Google logo ... If space is limited, the text 'Google Maps' is acceptable ... exactly 'Google Maps', not translated, translate=\"no\"") read 1 Nov 2026 (policies page, last updated 2026-10-30 UTC). The list shows the words "Google Maps" under the suggestions, start aligned, inside the same box. K-112 (Google's name only as plain words) is met: this is the one place the name is shown, because Google's policy requires it.
7. **Home hero** (`d6-home.tsx`): `overflow-hidden` became `overflow-x-clip` so the list is not cut at the hero's bottom edge (clip leaves the vertical axis alone). Nothing else on the hero changes.

## Google's current pricing for Autocomplete sessions that end in Place Details (read 1 Nov 2026)

- [Places API (New) price list](https://developers.google.com/maps/billing-and-pricing/pricing), last updated 2026-10-30 UTC: Autocomplete Requests (Essentials) 10,000 free a month, then 2.83 USD per 1,000 (first tier); Autocomplete Session Usage (Essentials) unlimited free, not charged; Place Details Essentials IDs Only unlimited free; Place Details Essentials 10,000 free then 5.00 USD per 1,000; Place Details Enterprise 1,000 free then 20.00 USD per 1,000.
- [SKU details, Places](https://developers.google.com/maps/billing-and-pricing/sku-details/places), 2026-10-30: when a session ends with a Place Details request, the first 12 Autocomplete requests of the session are billed at Autocomplete Requests and any later ones at Autocomplete Session Usage (no charge).
- [Session tokens](https://developers.google.com/maps/documentation/places/web-service/session-tokens), 2026-10-30: if the user selects a place, the session's autocomplete requests are bundled and only the place data request is charged; with no selection only the search queries are charged; a token without a selection is billed per request; reusing a token invalidates it. That page still describes Place Details (Legacy); the Autocomplete page says session use with Place Details (New) is "billed per session plus applicable Places SKUs". The two readings agree for Kabsi: a session that ends in Place Details costs the Place Details call, and typing on without choosing costs up to the Autocomplete Requests price.
- Kabsi's Place Details call carries the snapshot field mask (rating, opening hours, phone, website), which is the Enterprise tier: that call is the cost, and it is the same call as before this task. Worst case for the new part: the Autocomplete cap of 300 requests a day at 2.83 USD per 1,000 is 0.85 USD a day, and the first 10,000 requests a month are free, so nothing here is billed until about 33 days of full cap use in a month.
- Counting: `places_usage` (kind `autocomplete`) is the existing spend tracking; the day cap is `app_settings.places_autocomplete_daily_cap` (default 300, a non-number falls back to 300, never to no cap), with the same 80 percent and cap alerts as the other kinds. The Google Cloud quota for Autocomplete is a Rashid step (below).

## Independent review (a fresh agent, given only the diff and the rules)

Confirmed and fixed in the same pull request:
- High: a fast typist with a slow Turnstile could lose suggestions for the page (two waiting runs shared one token slot, an aborted run could take it, a timed out stale run switched suggestions off). Now a token queue like the free check's, a replaced run cancels its wait, a stale run never switches suggestions off.
- High to medium: a response for a replaced call dropped the pass the server had already issued, and a call that carried a Turnstile token could be aborted. Now the pass is always kept and a call with a token is not aborted.
- Low to medium: a pass that ran out (15 minutes, UTC midnight, a changed address) turned suggestions off for good. Now the server's `challenge_failed` makes the page ask once more with a fresh bot check.
- Low to medium: one visitor could use up the day's shared Autocomplete cap. Added 60 suggest requests a day per visitor.
- Medium: the chosen business name was put in the address (`pn`). Removed: the address carries the typed text, the Place ID and the session token only.
- Low to medium: the pick screen shows Places results without the attribution. Added "Google Maps" under the list. The result screen shows Places facts as before; its layout is Web 4's (LATER row).
- Medium to low: the saved check's "Change it" passed the old search term as the keyword. Now it passes none.
- Low: the highlighted option now scrolls into view in a shortened list.

Not changed: the pass is signed with the Turnstile secret, not a dedicated secret (acceptable, LATER row); a reload of `/scan?place=...&st=...` runs the check again with a used session token and takes one of the 3 checks of the day (LATER row).
