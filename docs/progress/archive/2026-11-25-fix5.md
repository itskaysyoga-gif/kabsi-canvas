# FIX-5: the bot check never leaves a dead button (25 Nov 2026)

Cause read from the code: the Send button was `disabled={!token}`, so with no token yet (script still loading, or Cloudflare waiting for a tap in a box nobody saw) it sat dead with no words. The widget gave up only at 10 seconds with a short line.

## What changed
- `src/lib/bot-check.ts` (new): the waiting label, the interactive hint, the slow line, the 15 second limit, button states, outcome names.
- `src/components/turnstile.tsx`: 15 second limit, hint above the box when a tap is needed, slow line versus error line, one `bot_check_finished` per attempt.
- `src/components/auth/sign-in-panel.tsx`: never disabled for a missing token; a tap waits and sends when the token arrives; script preloaded when the panel opens.
- `src/components/kabsi/scan-live.tsx`: waiting state on the search card and both forms; a missing token shows the slow card or line and sends nothing.
- `src/components/kabsi/business-combobox.tsx`: typing also starts the check (focus and press already did).
- `docs/EVENTS.md`, `docs/COPY.md` section 99, facts 11 (rebuilt with `node scripts/build-kb.mjs`).

## Evidence
- Sentry kabsi-web, "Turnstile failed", 14 days: 0 events. The project showed 0 unresolved errors in 14 days overall, so the zero is weak evidence.
- PostHog, 14 days: landing_viewed 73, free_scan_started 5, signup_started 0. `bot_check_finished` does not exist before this ships.
- Live `/api/suggest`: `warm` answers `{"ok":true,"configured":true}` in 1 ms (by design: it wakes the function and never carries suggestions, outcome "warm"); a suggest with no check answers 400 `challenge_failed`. A real suggestion needs a Cloudflare token, which only a browser can get; the handler is covered by tests/fix5-bot-check.test.ts for "barber Manchester" (outcome ok).
