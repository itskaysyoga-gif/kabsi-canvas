## 1. What changed

| Part | Where | What it does |
|---|---|---|
| The render step | `supabase/functions/_shared/whatsapp/look.ts` (new) | One module every in-scope reply passes through: the marker (the R-148 set plus star, clock, picture, receipt), a bold title of five words or fewer, the business after it only for a phone with several businesses or a change to Google, then the facts one per line, then one status or question. Quote lines for reviews and drafts. A standing note moves to the footer of a message with buttons or a list. A list of requests becomes a list message (10 rows, then "and N more"). `lookProblems` is the rule check the tests run |
| The agent | `whatsapp/agent.ts` | `answered()` sends every reply in scope (`IN_SCOPE`: request book, help, switch, off topic, hours, posts, photos, reviews and drafts, approvals, billing, hand-off) through look.ts, with no role head. Phones with no Kabsi role and every other reply are sent exactly as before. "Which business?" with 4 to 10 businesses is a list message whose rows are the existing `b:<id>` business buttons |
| The sender | `whatsapp/deliver.ts`, `whatsapp/kapso.ts`, `whatsapp/outbox.ts` | `buttons()` takes an optional footer (Kapso client `footerText`); a new optional `list()` (Kapso client `sendInteractiveList`); a sender without `list` sends the rows as text. The outbox record keeps the body and buttons as before |
| A row tap | `whatsapp/channel.ts` (`listRowText`) | A list row whose id is "#12" arrives as the words "#12", so the request opens by the existing path (`refOf`). Button replies, other list ids and routing are unchanged |
| The words | `whatsapp/say.ts`, `whatsapp/book.ts`, `request-book/replies/index.ts`, `request-book/extract.ts`, `whatsapp/alert-text.ts`, `review-growth/photo.ts`, `results-report/receipt.ts` | Each in-scope line written as "Title\nfacts\n\nstatus or question" (COPY.md 77). Request facts one per line; refusals get a short title; the review alert, post alert, photo ready and the weekly report's WhatsApp text are rendered with look.ts |

Kapso check (the send path is Kabsi's own code with `@kapso/whatsapp-cloud-api@0.4.0`): Kapso's TypeScript SDK page (docs.kapso.ai, interactive messages) shows `sendInteractiveButtons` with `header` and `footerText`, and `sendInteractiveList` with `buttonText`, `sections` and rows with `id`, `title`, `description`. The 0.4.0 package's type file (`dist/index.d.ts`, read from the npm package) has `footerText` and `header` (text, image, video, document) on button messages and `header` (text) and `footerText` on list messages. Quote lines are WhatsApp's own text formatting ("place an angle bracket and space before the text", faq.whatsapp.com 539178204879377); Kapso passes the text through. Limits used: 3 buttons, 10 list rows, row title 24, description 72, section title 24, button text 20, footer 60 characters. All four (header, footer, quote, list) are supported on the send path, so none falls back to the plain form. Headers are not used: the bold title stays in the body so that a message with no buttons, which cannot have a header, looks the same.

Not changed: button titles and ids, the order of buttons, routing (`router.ts` untouched), every approval path, the model's instructions (the two snapshot tests in `book.test.ts` pass untouched), templates, the database, the facts, the website.
