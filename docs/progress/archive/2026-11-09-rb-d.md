## What exists

| Part | Where | What it does |
|---|---|---|
| Extraction | `supabase/functions/_shared/request-book/extract.ts` | The model, `MODELS.check`, only quotes the exact words for each field of the pack's fixed schema, with the owner's text fenced as data (`<owner_message>`). Code finds each quote in the message after folding spacing, letter case, invisible characters and digit forms, and records where (positions point into `Extraction.text`, the trimmed message). It fills values with the RB-C2 normalizers, keeps a name or a detail as written, and decides what the owner sees. The model is an injected function (`Ask`): the file calls no network and reads no secret |
| Stored per field | `ExtractedField` | `raw`, `start`, `end`, `kind` (stated, inferred, absent, ambiguous), `normalized`, `normalizer` name and version, `candidates`, `validation`, `owner_action` (always null here), `needs_tap`, plus `show` and `display` for the owner |
| What the owner sees | `replyFor` | Stated plainly. Inferred with a question mark. Two or three readings are buttons (a tap saves that reading). Unknown is left out. Save is offered only when nothing needs a choice and the pack's required fields are there |
| Agreement rule | `readQuotes`, `locate`, `phoneField`, `whenField` | A phone or a time is used only where the model's quote and the normalizer agree (the quote overlaps what the normalizer read). A number or hour the normalizer finds where the model quoted nothing is not used: this is what keeps the 3 of "3am" in written-out Arabic from reading as an hour. Two numbers stay a question whatever the model quoted |
| Words not read | `whenField` | Words about when that no normalizer can read ("next week", an Arabic day word) are kept as written with "no time set". A time read next to unread words ("Thursday around three") is kept whole as words, not as the part that was understood. A date or time that cannot exist is unknown |
| Bare hours | pack field `likely_pm_hours`, `likelyPm` | Lane R decision on RB-C2 kept: the normalizer is unchanged and 1 to 7 stay ambiguous. New optional pack data: salon 1 to 7, garage 1 to 5, gym none. A bare hour in the list is shown as inferred (`Thu 3 pm?`), both readings stay on the record, and Save accepts it in one tap. Otherwise both readings are buttons. Never saved without the tap. A day that is itself unclear (Monday said on a Monday) stays two buttons, each with the afternoon reading |
| Claims | `claimHolds` | The model may quote words where the owner says the customer agreed, or that it is already booked or arranged elsewhere. Code keeps a quote only when it holds a statement word (confirmed, agreed, booked, with written-out and Arabic forms) and no word of doubt, need, request or denial sits beside it. The reply says "You said the client agreed. Kabsi records an agreement only when you tell it to." Nothing in the result sets a confirmation (PR B refuses one at creation) and Kabsi's own lines never use booked, available or confirmed |
| Prompt | `buildPrompt` in `extract.ts` | A new prompt, kept in the request book and not in `ai/prompts`, so the reply Prompt gate (CI job `prompt_gate`, which watches that folder) is unchanged. A guard test holds it |
| Eval set | `scripts/request-eval/cases.json` | 167 fictional cases: salon 61, gym 49, garage 57; English 78, Arabic 34, written-out Arabic 30, mixed 25. Vague times, a confirmation never stated (and one denied), a confirmation stated, a booking the owner states that Kabsi cannot verify, misspelled names, Arabic digits, digits used as letters, nothing to read (all four styles) and 13 injection attempts (all four styles). Arabic is in this fixture and the tests only |
| Runner | `scripts/request-eval/run.ts`, `eval.ts`, `live.ts` | `--mock` replays `recorded.json` by the hash of the exact prompt (a changed prompt or case has no recording and fails); `--oracle` answers exactly as each case expects (tests the cases against the code, says nothing about a model); `--live --budget N` calls the real model, refuses a budget above 5, stops starting cases near it, never uses `EVAL_LIVE` |
| Workflow | `.github/workflows/eval-live.yml` | New inputs `request_eval` (boolean, default false) and `request_budget` (default 5), one new step, and the new result files in the artifact. No existing step, condition or default changed. Listed for lane R |
| CI | `scripts/deno-check.sh` | Type-checks `scripts/request-eval/` and runs its tests (no network, no model). Listed for lane R |

## The hand run on the real model

Dispatched on `claude/rb-d` as Eval live run 42565005690 with `evaluations` false, `injection` false, `pages_only` false and `request_eval` true, so no other evaluation ran. Model `claude-haiku-4-5-20251001` (`MODELS.check`), 167 calls, one each. **Spent 0.1473 US dollars** of the 5 US dollar cap; the run stopped by itself at the end of the set. The answers are saved as `scripts/request-eval/recorded.json` (the model's words for fictional messages only; Arabic written as escapes).

First read of the marks, before any fix:

| Mark | Result |
|---|---|
| Stated with no matching quote | 0, pass |
| Fully stated phone normalized correctly | 24 of 24, pass |
| Ambiguous flagged, not silently resolved | 29 of 30, 96.7 percent, pass |
| Field accuracy: English, Arabic, written-out Arabic, mixed | 96.4, 96.2, 90.1, 96.5 percent, pass |
| Invented figures | 0, pass |
| Output implying a confirmation or booking not stated | **2, fail**: the model quoted "ok" in Arabic (gym-mx-05) and "he will bring it Thursday at 9" (garage-en-43) as an agreement |
| Injection breaches | 0, pass |

Fix round 1 (code only, so the same recorded answers replay through it, and the prompt hash is unchanged): the claim rule above. After it every mark passes on the recorded answers. Fix round 2: the independent review (below) showed the first version of the rule was too loose; it is now word-level, and the numbers did not move. I did not need the second round for the marks.

Honest reading: the two failures are the real model's slips; the guard was added after seeing them, so the 0 on that mark in CI is measured on answers the code was tuned to. The review's list of unseen phrasings (requests, waits, modals, denials, "disagreed", "Book Sarah") is now a unit test. The margins are thin in two places: written-out Arabic 90.1 percent and ambiguous 96.7 percent. Those misses are the model returning null or a wider quote ("Nadia Sunny", "Ali akkad"), not code. A re-recording on a changed prompt could land below a mark; the report would then say so.

## Known limits and for later

- Not wired to WhatsApp (RB-E). Vehicles and plates are text details as written (a plate or a make is not checked or normalized); the design's plate and make lookups are a later module.
- Day words the normalizers do not know (an Arabic day, "el jom3a") are kept as words with no time; a day word in Latin letters is read only for the forms RB-C2 lists. `tomorrow 10.` with a full stop right after the hour is not read as an hour (RB-C2 normalizer, left as built); the words are kept with "no time set".
- The check model quotes from one message only; two people in one message are not split.
