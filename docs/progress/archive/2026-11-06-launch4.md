## Part A: the live speed gate

### Why kabsi.co carried more script than the CI build

Lighthouse 12 (390 px, mobile), run from this session's machine against kabsi.co and against the CI-style build (`scripts/serve-compressed.mjs`, HTTP/2, brotli 4), with the script lists side by side (`network-requests`, every script file):

| | Home | Pricing | /scan |
|---|---|---|---|
| kabsi.co (before) | 215.1 KB, 49 files, LCP 2.48 s | 227.5 KB, 58 files, LCP 2.22 s | 243.0 KB, LCP 2.08 s |
| CI build (before) | 204.2 KB, 50 files, LCP 2.11 s | 213.7 KB, LCP 1.96 s | 226.9 KB, LCP 1.96 s |

- Same files on both. Nothing Vercel, Sentry or consent adds falls inside Lighthouse's window on these pages: the Meta Pixel (fbevents.js and its config, 255 KB), PostHog (/ingest, 141 KB) and Speed Insights load later (a plain Playwright visit that waits for network idle plus 4 s sees them; Lighthouse does not). The Sentry loader (2.8 KB) is on both.
- The gap, file by file: every script response on Vercel carries about 0.1 to 1 KB more than the CI server's, its response headers, which Lighthouse counts (the page header set, about 1.6 KB raw, on each `/assets/*` file: content policy, frame, referrer and permissions policy, plus Vercel's own etag, disposition, age, id); the entry script is 1.3 KB larger raw with the production env values and 2.8 KB more on the wire. Vercel's edge brotli of the entry (127.5 KB) is close to CI's quality 4 (125.0 KB).
- The CI build loads `tz-country` (4.2 KB) that kabsi.co does not (the live server knows the country), which hides part of the gap in CI.
- Served locally with Vercel's headers copied onto every asset, the CI build read Home 210.6 KB and Pricing 221.9 KB: the headers alone explain most of the gap.

### What changed (PR 445)

1. The FAQ lists left the shared entry script. Route heads run in the entry chunk on every page, and the FAQPage markup of Pricing, Founding, Partners and FAQ pulled `faq-data.ts` and `lib/faq.ts` (16 KB raw) into it. The heads now build that markup on the server only (`serverOnlyLd` in `src/lib/site.ts`); `faqJsonLd` has no default list. Server HTML FAQPage is byte-identical to kabsi.co on all four pages; after hydration the full block is still in the page; after a move inside the site the block names the new page (`{"@id": ".../pricing#faq"}`), never the old page's questions. Entry script 390 to 374 KB raw.
2. `/assets/*` sends HSTS and nosniff only; every other path keeps the full set (vercel.json; `tests/security-headers.test.ts` checks both). Locally, with Vercel-like headers, this took Home 210.6 to 207.9 KB and Pricing 221.9 to 218.3 KB.
3. Fonts are never inlined into the render-blocking stylesheet (a Cyrillic font was, 2.7 KB compressed of 24 KB).
4. LCP: the simulated LCP breakdown on kabsi.co was TTFB 600 ms and render delay 1,880 ms; the HTML of Home took 0.29 to 0.59 s to the first byte (static files 0.14 to 0.16 s), because every visit rendered it again in fra1. The sitemap's fixed public pages (not the guides or industry pages, which list guides published on a schedule) now send `public, max-age=0, s-maxage=600, stale-while-revalidate=86400`, so Vercel's edge keeps a copy; a deploy starts a new cache. Their HTML is the same for every visitor (two fetches differ only in the router's render timestamp; no cookie or header is read on the server). `tests/edge-cache.test.ts`.

Not done, tried: grouping the many small chunks with rolldown `codeSplitting` groups. Every setting tried (minShareCount 2 to 20, maxModuleSize 1.5 to 3 KB, with and without dependencies) raised Home's script to 257 to 303 KB, because a shared group pulls code from other routes; reverted.

## Part E: the Conversions API (PRs 443 and 448)

- `metaDatasetId()` keeps only the digits of META_PIXEL_ID ("ID 2179603053433551" becomes "2179603053433551"); with no digits it logs one `meta_dataset_missing` line and sends nothing. A refused dataset logs one `meta_dataset_refused` line with the status, Meta's code and subcode and the id's length only. Both senders use it (`meta-capi-web.ts` for Lead and FreeScanCompleted, `sendCapi` for the rest).
- Review fixes (PR 448): only code 100 with subcode 33, or the words "does not exist", count as a refused dataset (code 100 alone also covers a stale or badly formed event); when the clear line is logged, the thrown error is a fixed `meta_capi_web 400 dataset_refused`, so no words of Meta's answer reach the log or Sentry for it.
- Tests: `_shared/meta-capi-dataset.test.ts` (the labelled secret posts to `/2179603053433551/events`; no digits sends nothing; the refusal line carries no token, ids, cookies or Meta's text; the thrown message; code 100 with another subcode is not a refusal).
- Live: the consent function's log since 09:00 UTC holds one Conversions API line, the 10:39:15 UTC refusal ("Object with ID 'ID 2179603053433551' does not exist"). No free check with ads accepted has run since, so the accepted server event is not seen yet (Rashid's step).
