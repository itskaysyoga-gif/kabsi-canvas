## The fix, and why it was taken back

Run 1's failure was fixed in `supabase/functions/_shared/nora-rules.ts` (commit eeb1603): one clause on the booking line, "In another language, keep the name Google Business Profile exactly as written in English; never translate it." The one allowed rerun of the failed case (sc05, run 2) was worse: the model read "in English use exactly these words" and the new clause together as a reason to print the English sentence in a Spanish reply. A change that makes the live answer worse is not kept: the clause was taken back by a revert commit, so `nora-rules.ts` is the same as on main. Nothing of Nora's behaviour changed in this pull request. No further run was made: the task allows one rerun, and another 0.28 USD would have taken the total to the 1 USD stop.

What a later Nora session can do (LATER row added): either word the booking line so that only the product name stays English (for example give the Spanish sentence as the set answer next to the English one, as the Spanish hand-off lines already are in `say.ts`), then rerun sc05 once (about 0.3 USD); or decide that "perfil de empresa en Google" is an acceptable Spanish rendering and let sc05 accept it (a change to the question's `must`, which is lane R's call because it relaxes a check; it was not done here).
