## Part D: the cause, reproduced on production first

With motion on, as most visitors have it, a click from /for at 1,897 to 3,877 px opened the next page at the old position and slid it up over about a second. For example, /for/spa-and-massage read 3590, 1530, 340, 30, 0 px at 250 ms steps. The repo's Playwright config runs with reduced motion, which is why no earlier test saw it. The cause was `html { scroll-behavior: smooth }` in src/styles.css, which also animated the router's own jump to the top. After the fix, the same run reads 0 px at every step on a local build and on production.

## Part B: the independent review (a fresh agent given only the diff and the rules)

There were no high findings. Fixed:
1. The session-ended screen's "Sign in again" showed Home's "You are signed out." and could go Home. It now signs out quietly and the log in page says "Your session ended. Log in again."
2. Staff could get past the 12 hours by opening the website first. Staff pages now keep their own last-visit stamp.
3. A failed is_staff answer counted as "not staff". It is now asked again, and nothing is recorded on a staff page until the answer is in.
4. A stale stamp could sign out the next person. It is cleared when no session is found.
5. A leftover Google code verifier showed Dashboard. Only the session key counts now.
6. Time away found on a website page now opens the log in page.
7. A reason left unread now expires after 10 minutes.

The review also found an old bug: the last-visit stamp was cleared on every page load before the session was read, so the 30 days never applied on load. That is fixed too.
