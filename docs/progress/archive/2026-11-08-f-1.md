# F-1: a forwarded Yes is not the owner's yes (8 Nov 2026)

The defect: a message the owner forwarded that read "Yes" counted as the owner's own Yes and could approve something for Google. parseWebhook did not read the forwarded marker.

## The field

- Meta's Cloud API messages webhook (text message reference): `context.forwarded` is true when the message was forwarded 5 times or fewer, `context.frequently_forwarded` when more than 5. A reply's `context` carries only `id` and `from`.
- Kapso's v2 `whatsapp.message.received` (docs.kapso.ai, Message events): the `message` object is Meta's message object (`from`, `text`, `interactive`, `button`, `referral`, `contacts`, the same keys Kabsi already reads and Rashid's live test of 25 Oct proved) plus `message.kapso`. Kapso's own TypeScript SDK (`@kapso/whatsapp-cloud-api` 0.4.0, `MetaMessage`) types `context?: MetaMessageContext | null` with open keys, so Meta's context reaches Kabsi as Meta sent it. Kapso's docs page does not name `forwarded` itself. The Kapso connector was not used (R-49).
- No live forwarded message was sent (no live WhatsApp send in this session). A live check is listed below for Rashid.

## What changed

- `channel.ts`: `Inbound.forwarded: boolean`, from `message.context.forwarded` or `message.context.frequently_forwarded`. No context, or a reply's context, reads false.
- `router.ts`: forwarded text is never yes, no, a number or an owner or staff code; it goes the free-text path. A forwarded yes word is marked `forwardedYes`. STOP still wins first. Buttons are read before any of this and are unchanged.
- `agent.ts`: a forwarded yes with something waiting for the owner's yes approves nothing and answers `SAY.forwardedYes`. Forwarded words never answer the setup question or the photo kind menu. Words held for the role or business question keep their forwarded mark (`roles.ts`, `forwarded?: true` on those two open questions), so a forwarded Yes read again after the pick is still not a yes.
- `say.ts` and `docs/COPY.md` section 68: "That looks forwarded, so I did not count it as your yes. Tap Yes, or type it yourself."
- Facts: `knowledge/facts/01-decisions-coming-and-changing.md` (WhatsApp for owners), then `node scripts/build-kb.mjs`.
- Messages stored before this change have no `forwarded` key; they read as not forwarded, as before.

## Tests added

- `whatsapp.test.ts`: the marker from both flags; none, null, a reply's context and `forwarded: false` read false.
- `agent-units.test.ts`: the router on forwarded Yes, ok, No, 2, owner and staff codes, STOP in three languages, a forwarded button, and the same words typed.
- `conversations.test.ts` (10 cases, tag F-1): forwarded Yes approves nothing and the item stays waiting; typed Yes after it approves; the Approve button after it approves; two items waiting, no Which one and no approval; a forwarded number does not pick from Which one; a forwarded Yes with nothing waiting takes the free-text path; forwarded STOP stops; forwarded owner code and staff code do not bind; the role question's held words stay forwarded after the pick.
